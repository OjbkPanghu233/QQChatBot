NapCat 在 Docker 内运行，Python 连接程序和 Ollama 在 Mac 本机运行。

## 日常使用：只打开一个脚本

在 Finder 中双击 **`启动仪表盘.command`**，会启动独立网页管理服务并打开 **http://127.0.0.1:8765**。重复打开会复用已有服务，不会重复启动机器人，也不会主动启动聊天机器人。

之后统一在网页操作：

- **组件管理**：启动、停止、重启机器人；管理 Ollama 服务、模型内存和 NapCat 容器。启动机器人会自动准备所需服务，必要时打开 Docker Desktop 并等待其就绪。
- **模型人设**：读取、修改 Modelfile，保存文件或保存并构建模型；本地试聊实时显示思考和回复，试聊不会发送到 QQ。
- **运行设置**：选择已有模型，开关思考，调整上下文、生成额度、超时、插话概率和冷却；配置群号、管理员及本机连接地址。保存时自动重启正在运行的机器人，已停止时只保存。
- **用户消息池**：搜索、查看发言池，编辑人物备注，清空个人消息池或全部对话记忆；清空需要在网页确认。
- **运行日志**：查看机器人、Ollama、NapCat 和管理台日志；下载本次运行的输入消息、思考及最终回复，或下载已归档文本。
- **QQ 登录**：在嵌入的 NapCat WebUI 扫码登录；也可从网页独立打开 WebUI。

**停止机器人不会关闭管理网页**，因此可以继续查看消息池、修改配置并重新启动。关闭浏览器标签也不会停止后台组件；需要停机时先点击对应的停止按钮。QQ 未登录时，即使机器人进程已启动，也不会收到群消息。

管理服务和机器人分别由 launchd 管理，已启动的服务可以在登录后恢复。机器人停止按钮会移除机器人的登录自启；再次从网页启动后恢复。

当前不保留旧路径兼容链接。Ollama 原生后台服务通过 `OLLAMA_MODELS` 读取 `runtime/ollama/models`，NapCat 容器直接挂载 `runtime/napcat/data`，模型权重没有重复复制。Docker Desktop 和 Ollama 引擎仍使用本机已有安装。

`runtime/` 和 `.local/` 不提交 Git；完整备份应包含这两个目录。目录与迁移说明见 [WORKSPACE.md](WORKSPACE.md)。`manage.py`、`botctl.py`、`ollamactl.py`、`webctl.py` 是网页调用的内部管理工具，日常使用无需终端。

## WebUI 仪表盘

管理台监听本机 `8765` 端口，机器人内部状态接口监听 `8766`。两者分别运行；管理台会在机器人停止时显示已保存的个人消息池和停止状态。

- 查看 QQ / NapCat 连接、Ollama 服务及模型加载状态、任务队列、本次运行的收发统计。
- 实时查看消息入队、整理上下文、模型思考、生成回复、清洗及发送阶段。Ollama 采用流式输出，思考和回复草稿边生成边更新；只有最终清洗后的文本会发送到群里。
- 查看本次实际送入模型的聊天上下文、执行时间线、输入输出 token 数，以及 OneBot 是否确认发送成功。
- 点击最近任务回看思考和回复；点击「跟随实时」切回正在执行的任务。保留本次运行最近 20 个任务，思考内容只保存在内存中，不写入日志或消息池；单任务展示内容最多 24576 字符。
- 搜索群友昵称、曾用名或 QQ 号，查看实时个人消息池、累计发言、点名次数和管理员备注。页面直接读取当前内存，无需等待 60 秒自动保存。

界面约每秒更新一次。管理服务仅监听 `127.0.0.1`，控制请求校验同源地址和 CSRF Token；机器人内部接口另有本机认证 Token。OneBot Token 不在设置中回显，日志展示会遮盖已配置的 Token。群聊正文按纯文本显示。

当前任务详情保存在内存中，重启机器人后不会恢复；重要记录请提前从网页导出。停止时管理台可暂时保留最后一次读取的任务，但这不等于永久归档。模型测试与群聊任务分别展示。

## 在群里使用

采用「像群友一样插话」的策略，所有群成员都可以正常聊天：

- 被 @、被回复，或者文字里包含「鲸鱼」「大肥鱼」「小鲸子」「deepseek」时必须回复。
- 其他普通消息按网页中的插话概率和冷却时间触发插话；当前设为 100% 和 0 秒。模型仍可以输出 `[SKIP]` 放弃插话，因此 100% 触发不等于每条必回。
- 插话排队超过 30 秒就不再生成；开始生成后单独按模型的 300 秒超时计算，点名回复也遵循此生成上限。生成中的插话也会占用插话名额，避免连发。
- 回复直接发送纯文本，不引用消息；保留原代码的一到两句、最多约 60 字的清洗规则。

指令仅对 QQ 用户 `3102896704` 有效：

| 指令 | 用途 |
| --- | --- |
| `/ai 问题` | 强制回复 |
| `/reset`、`/ai /reset`、`reset`、`清空记忆` | 清空全群滚动聊天记录和所有成员的个人发言池，并让重置前排队中、生成中的回复失效；昵称、统计、人物备注保留 |
| `/note 昵称 备注` | 为已出现的群友添加备注，支持曾用名；昵称含空格时暂不支持 |

其他成员发送指令会被忽略，不执行指令也不调用模型。未知斜杠指令同样忽略。

## 消息池与上下文

只处理指定群的新消息，忽略私聊、其他群及机器人自身消息。可在 `.local/config.json` 配置 `ignore_user_ids` 忽略其他机器人账号。

- 全群共享最近 50 条滚动记录，保留昵称及「回复谁」标记；单次送入模型的聊天记录最多约 4000 字符，按时间从旧到新裁剪。人物资料、人设、当前消息另计，50 条不保证全部进入单次请求。
- 每人保留最近 40 条个人发言，每条最多 120 字；图片和表情只记录占位符，不进入个人发言池，也不识别图片内容。
- 每次请求选取最近参与者中最多 4 人的资料；当事人最多补充 3 条窗口外的早先发言。
- 入队时同时冻结群记录和人物资料，后续新消息不会混入旧任务的上下文。
- 当前待回复消息单独标注；背景最多保留两条不同的机器人旧回复，防止重复内容不断强化。较长回答如果与旧回复完全相同，会仅根据当前消息重试一次；仍然重复则不发送。
- 个人池、昵称、统计和备注保存到 `.local/profiles.json`，每 60 秒保存一次；正常停止、SIGTERM 或 Ctrl+C 时也会保存。全群滚动记录只保存在内存中。
- 消息池属于上下文补充，不会训练或修改模型权重。

## 人设、参数和记忆

**模型人设 → 保存并构建模型** 会把 `models/deepseek.modelfile` 应用到当前选中的模型；仅保存文件用于暂存编辑。Python 继续使用模型内置 SYSTEM，项目中的 `prompt.txt` 不参与当前群聊。保存前会保留少量配置备份于 `.local/settings-backups/`。

**运行设置**中的上下文和生成额度属于机器人每次请求的参数，可以覆盖模型对应默认值，不会修改模型权重。开启思考并增加上下文会增加内存和等待时间；当前 16GB Mac 使用 8K 上下文，生成额度 2048 包含思考与最终回复，额度过小可能截断最终回复。

修改运行设置会自动重启正在运行的机器人，全群滚动记录随进程重启清空，个人消息池从文件恢复。若需要清空全部对话记忆，使用网页中的对应按钮或管理员 `/reset`，昵称、累计统计及备注保留。清空个人池不会删除全群滚动记录。

Mac 休眠、Ollama 停止或 QQ 未登录时无法回复。OneBot 断开后自动重连；退出终端不影响后台服务。连接异常可在网页查看日志、打开 QQ 登录面板或执行“检查群连接”，无需终端。
